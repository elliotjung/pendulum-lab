# 다중 run 실험: 비교·sweep·ensemble·적분기 비교

S21은 `next.html#/lab/{systemId}`의 **Experiment Tray → 비교 · sweep · ensemble · 적분기 비교**에서 제공한다. 현재 실험의 canonical 입력을 복사해 실행 계획을 만들며 원래 실험은 변경하지 않는다.

## 실험 설계

| 유형 | 설계 | 해석 |
|---|---|---|
| 두 조건 비교 | 원래 실험과 변수 하나만 바꾼 실험 | 원래 조건이 대조군이다. 다른 입력·seed·실행 기간을 유지한다. |
| 선형 격자 | 축별 시작·끝을 포함하는 등간격의 Cartesian 곱 | 전체 run 수는 축별 점 수의 곱이다. |
| 로그 격자 | 양의 시작·끝 사이의 로그 간격 Cartesian 곱 | 0과 음수 구간은 거부한다. |
| Latin hypercube | 각 축을 같은 수의 층으로 나눈 뒤 seed로 독립 순열·층 내 표본화 | 축마다 각 층을 정확히 한 번 사용한다. 결합 분포의 전수 탐색은 아니다. |
| Seed ensemble | run별 seed와 선택적인 독립 균일 변수 표본 | 결정론적 모델은 seed만 바꾸면 동일 결과가 나올 수 있다. |
| 적분기 비교 | 실제 adapter가 지원하는 방법을 동일 입력·seed·step·기간으로 실행 | 첫 번째 방법은 비교 기준이며 참해가 아니다. |

고정 간격 오차 감시와 적응 간격 승인·거부는 다른 계산 경로다. 분할 적분의 심플렉틱 보장은 좌표와 모델의 전제를 따른다. 카탈로그에 존재한다는 이유만으로 현재 adapter가 실행하지 않는 방법을 노출하지 않는다. 내부 전용 stepper의 비교는 설명과 함께 거부한다.

현재 선택형 adapter의 비교 방법은 Euler·RK2·RK4 중 실제 허용되는 조합이다. 기존 `runExpansionSuite`의 추가 적분법·ghost·분기·선택적 Lyapunov·순위 산정과 `energyDriftProfile`의 추세 기울기·R²·secular 분류를 이 요약 UI가 제공한다고 해석하지 않는다. 해당 기존 API·코드·앱은 보존했다. 임의의 구동 위상·제어기·topology를 기존 runner의 기본값으로 바꾸어 같은 실험이라고 주장하지 않는다. S28의 전체 기능 동등성 심사는 별도다.

LHS 좌표는 기존 연구 모듈의 `latinHypercube`가 직접 생성한다. 물리 범위 환산만 새 계층이 담당하며 native 좌표와의 정확한 일치를 검사한다. runtime의 `configured*` 복제 필드와 배열을 함께 바꿔야 하는 grid 차원은 단독 sweep 변수에서 제외한다. 전체 원본 설정은 export에 보존한다.

## 대기열과 복구

- 계획 순서와 run ID를 실행 전에 고정한다. worker의 완료 순서가 달라도 같은 입력·seed는 같은 계획·집계를 만든다.
- 동시 worker 수를 제한한다. 진행률은 실제 완료한 단계와 run을 바탕으로 표시한다.
- 취소하면 실행 중인 worker를 종료하고 완료 결과를 보존한다. 재개는 완료 run을 재계산하지 않고 미완료 run을 원래 입력·seed에서 다시 시작한다. 진행 중인 확률 stream의 cursor를 이어 붙인다는 의미가 아니다.
- 개별 실패는 run ID·시도 횟수·오류와 함께 기록한다. 실패 run만 다시 실행할 수 있으며 다른 완료 결과를 바꾸지 않는다.
- 전체 설정과 완료·미완료·실패 상태를 파일로 저장하고 재개할 수 있다. 파일 가져오기 실패는 현재 계획을 교체하지 않는다.

한도는 512 run, 동시 worker 4개, 변수 3개, 개별 run 100000 step, 관측 성분 512개, 전체 추정 작업 4000000, 파일 16 MiB다. 실행 중 worker가 30초 동안 응답하지 않으면 해당 run만 실패로 기록한다. 모델별 실제 계산량과 장치 성능은 이 추정값과 다를 수 있다.

## 결과의 의미와 계보

각 run에는 canonical 입력 snapshot, 변경한 변수·단위, seed·생성기 버전, 적분기·실행 설정이 있다. 집계 artifact는 입력 snapshot ID와 개별 run ID를 참조한다. 이는 S21의 다중 실험 파일 내부 계보이며 S24의 연구 project 저장소를 의미하지 않는다.

성분별 요약 통계는 기록한 표본의 산술 통계다. `sampleEvery`에 의존하고 시간 가중 평균이 아니다. 서로 다른 단위를 가진 상태 성분을 하나의 물리적 거리로 섞지 않는다. 집계 분산은 run 간 표본 산포이며 자동 신뢰구간·정확도 보장이 아니다. 두 조건의 차이도 인과성·통계적 유의성을 증명하지 않는다.

구동·감쇠·제어가 있는 모델의 에너지 변화는 보존 오차와 다르다. Langevin의 상태 신호는 member-1이고 에너지는 내부 ensemble 평균이므로 동일 궤적의 에너지 수지로 해석하지 않는다. 정적 lattice/FK/Floquet 평가는 실제 평가 결과를 표시하며 존재하지 않는 시간 진화를 만들지 않는다. 원시 궤적 전체는 다중 run 요약 패키지에 저장하지 않는다.

입력 plan은 기존 canonical/schema와 adapter의 물리적 검사를 통과해야 한다. 외부 파일은 버전·필드·크기·입력/결과 연결·집계를 검사한다. 외부 수치값을 재계산하거나 출처를 인증하는 기능은 아니다. ID는 재현 가능한 식별자이며 암호학적 인증 서명이 아니다.

## 보존과 검증 경계

기존 `app.html`, 물리·카오스·연구·runtime·worker·validation 엔진, 공개 API, 기존 저장·공유 형식, package/lockfile, 과학 golden과 이전 테스트·PNG를 보존한다. 새 UI와 계산 orchestration은 product 계층에서 기존 physics adapter를 호출한다.

구현·검증·실패 이력·정확한 자원 한도·commit/push 증거는 `stage-runs/S21-progress.md`, `S21-verification.json`, `S21-preservation.json`에 기록한다. 사람의 과학 검토를 수행했다고 주장하지 않는다. S21은 사용자 review checkpoint가 아니며 다음 review checkpoint는 S24다.
