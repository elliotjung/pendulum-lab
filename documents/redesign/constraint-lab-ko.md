# S11 — 용수철·줄·이중 줄 실험실

## 범위와 사용 경로

새 병렬 앱의 `next.html#/lab/spring`, `next.html#/lab/rope`, `next.html#/lab/double-string`에서 세 시스템을 설정하고 실행한다. 기존 `app.html`과 원래 물리 엔진은 유지한다.

- 용수철: 질량, 용수철 상수, 자연 길이, 반지름·각도와 속도, RK4/RK2/Euler.
- 줄: 질량, 최대 길이, 중력, 선형 감쇠, 초기각·각속도와 원래 사건 적분기.
- 이중 줄: 두 질량·길이·초기각·각속도, 중력, 기존 혼합 감쇠 계수와 원래 사건 적분기.
- 공통: 실행/일시정지/재개/한 단계/취소/초기화, 길이·힘·에너지·Cartesian 궤적, 초기조건 저장/가져오기/공유, 설정 보관함, CSV와 SVG.
- 사건 프리셋은 초기 이완·재포획, 실제 장력 0 교차, 바깥 줄 이완과 두 줄 자유 비행을 구분한다. 용수철에는 방사 진동과 압축 예제를 제공한다.

## 수치 의미와 한계

계산은 `rhsSpring`/`energySpring`, `RopePendulum`, `DoubleStringPendulum`을 호출한다. 운동방정식을 새 UI에 복제하지 않는다. 각도는 아래 수직선 기준 rad, Cartesian 위치는 고정점 기준 m이고 위쪽이 y 양수다. UI와 내보내기에서 줄 엔진의 단위 질량당 에너지·장력·포획 손실은 질량을 곱해 J·N으로 변환한다.

용수철 힘은 `k(r−L₀)`이며 압축에서는 음수다. 원점 근처에서는 극좌표가 특이해지므로 product adapter가 적분 중 반지름을 검사하고 마지막 유효 상태에서 중지한다. 강성이 크거나 질량이 작은 계의 안정 시간 간격을 자동 보장하지 않는다.

줄의 느슨한 구간은 장력 0이며 줄 길이가 최대 길이보다 짧아지는 것이 정상이다. 화면은 최대 길이와의 차이와 실제 구속 위반을 따로 표시한다. 비활성 구속의 위반은 초과 길이만, 활성 구속의 위반은 절대 길이 잔차로 계산한다. 느슨한 줄의 굽은 파선은 상태 기호이며 줄 자체의 형상을 푼 결과가 아니다.

사건 목록은 적분기가 내놓은 순서를 유지한다. 초기조건 장력 판정으로 발생한 이완과 적분 중 검출한 0 교차는 별도로 기록한다. 사건 잔차의 단위는 이완에서 N, 재포획에서 m다. 초기 이완의 기존 엔진 잔차 0을 정밀한 0 교차의 증거로 해석하지 않는다. 사건 시각은 원래 적분기의 근사값이며, 한 출력 간격 안의 모든 미세 사건을 완벽하게 검출한다는 보장은 없다.

이중 줄은 `taut`, `outer-slack`, `full-slack` 세 모드의 기존 근사 모델이다. 안쪽만 느슨하고 바깥쪽만 팽팽한 모드는 따로 풀지 않는다. 일부 자유 비행·재포획에서는 큰 길이 잔차와 에너지 증가가 생길 수 있다. 누적 포획 손실은 엔진이 기록한 손실 항의 합이며 전체 에너지 오차를 보정하지 않는다. 감쇠는 팽팽한 모드의 힌지 토크와 느슨한 모드의 선형 감쇠에 다르게 적용되어 단일 SI 마찰 계수로 해석할 수 없다. 정량 에너지 비교에는 감쇠 0, 간격 수렴과 구속 잔차를 함께 확인한다. 이러한 한계를 가리는 물리 엔진 수정은 하지 않았다.

이를 확인한 수치 fixture는 기본 질량·길이·중력과 감쇠 0에서 초기 상태 `[2.5,2.5,0,0]`, 간격 0.002 s, 기간 2 s다. 원 엔진과 새 연결 모두 최대 약 0.4352688973 m 초과 길이와 바깥 줄 재포획 전후 약 5.3233191174 J 에너지 증가를 낸다. 이는 물리적으로 정확한 비탄성 구속 해라는 인증이 아니라 보존된 기존 모델 한계를 재현하는 검사다.

줄에는 일반 강체 적분기나 매끄러운 tangent 기반 카오스 분석을 노출하지 않는다. 저장된 호환 분석 설정은 계약에 따라 보존하지만 S18 이후 분석 실행 기능을 이 단계에서 구현하지 않는다.

## 저장·공유·내보내기

`pendulum-experiment/v1`에 `constraint-model-v1`과 `constraint-integrator-v1`을 사용한다. 기존 S03 계약을 바꾸지 않는다. canonical 값·단위, 시작 시각·기간·기록 간격, seed·출처·분석 설정은 왕복 보존한다. 지원하지 않는 버전·단위·필드·옵션·분석은 조용히 버리지 않고 거부한다.

JSON 저장과 공유는 **초기조건에서 재시작하는 설정**이다. 실행 중의 Cartesian slack 상태를 각 초기조건으로 잘못 해석하거나 중간 사건 상태를 그대로 재개한다고 표시하지 않는다. 일시정지 후 재개는 살아 있는 같은 worker에서만 정확한 내부 상태를 유지한다.

- 로컬 저장 키: `pendulum-product/constraint/v1/<systemId>`.
- 손상·미래 버전·다른 시스템의 기존 저장값은 덮어쓰지 않는다. 입력 파일은 UTF-8 200,000 bytes 이하이며 위험한 객체 구조와 잘못된 수치를 거부한다.
- 보관함은 같은 문서의 최근 8개 시스템/공유 설정에 각각 최대 12개 설정을 보존한다. 화면 이동 시 worker와 궤적은 해제하며 새로고침 후에는 명시적으로 저장한 설정만 복원한다.
- 궤적 CSV는 보관한 표본과 마지막 수신 상태를 담는다. 모든 적분 단계를 뜻하지 않는다. 사건 CSV는 표본 축약과 독립적으로 수집한 사건 전체를 담는다.
- 사건이 없는 경우 사건 CSV 버튼을 비활성화한다. CSV 셀은 유한한 수와 검증된 고정 enum으로 제한한다.
- SVG는 현재 선택한 그래프와 링크, 설정 metadata를 포함한다. 선당 약 600점으로 축약하며 포획의 불연속 순간을 연결선이 정확히 나타내지는 않는다.

## 자원과 실패 처리

계산은 전용 worker에 격리한다. 실행당 최대 100,000 단계, 보관 표본 최대 2,001개, 사건 최대 10,000개다. worker 요청은 최대 64단계이며 단계 사이에서 8 ms 예산을 확인한다. 단일 기존 엔진 단계는 분할 취소하지 못하지만 worker 종료로 중단할 수 있다. 응답 제한은 15초다.

취소·오류·화면 이동은 실제 worker를 종료하고 늦은 응답을 무시한다. 계산 실패는 마지막 유효 표본과 사건을 보존한다. 잘못된 입력·알 수 없는 worker 응답·실행 ID/순서 불일치는 실행 결과로 받아들이지 않는다.

## 검증과 보존

실행한 검사 결과와 보고서 hash는 `stage-runs/S11-verification.json`, 각 checkpoint와 push 증거는 `stage-runs/S11-progress.md`에 기록한다. S11 완료는 별도 완료 상태 commit을 원격에서 확인한 뒤에만 인정한다.

기존 physics/chaos/research/runtime/workers/validation, 공개 API, 기존 데이터, S03 계약, S01 golden, lockfile과 기존 시각 기준선은 유지한다. 사용자 구조 승인 기록은 S07/S09이며 S11에는 별도 승인 게이트가 없다. 자동 수치·UI 검증은 물리 전문가 검토나 실제 보조공학 기기 검토를 대체하지 않는다. 기존 보안 경고는 해결 또는 위험 수용으로 표시하지 않는다.

복구 기준은 완료된 S10 `73b7773c5ae9b00c00aecfb899937a53af1b8acf`이며 기존 앱은 계속 접근 가능하다. S12 시작, 기본 앱 전환, master 병합과 릴리스는 이 작업에 포함하지 않는다.
