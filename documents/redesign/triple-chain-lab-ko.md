# S10 — 삼중진자와 N중 사슬 Lab

## 실행 결과와 화면

새 Lab의 삼중진자와 N중 평면 진자는 기존 물리 엔진으로 실제 계산한다. 삼중진자는 정확히 3개 링크, 사슬은 1–128개 링크를 지원한다. 시스템 목록에서 선택하면 조건 편집, 실행·일시정지·한 단계·취소, 링크별 그래프, 저장과 내보내기를 사용할 수 있다.

개발 서버 `npm run dev`를 실행한 뒤 다음 주소를 연다.

- 삼중진자: `http://127.0.0.1:5173/next.html#/lab/triple`
- N중 사슬: `http://127.0.0.1:5173/next.html#/lab/chain`
- 기존 앱: `http://127.0.0.1:5173/app.html`

조건 패널의 `편집할 링크`는 고정점에서부터 센 순서다. 선택한 링크의 질량(kg), 길이(m), 시작 절대각(rad), 각속도(rad/s)를 편집한다. N중 사슬은 선택한 링크 뒤에 추가하거나 선택 링크를 삭제할 수 있다. `링크 수 N`을 바꾸면 끝부분을 늘리거나 줄인다. 보존되는 링크의 각도와 각속도는 상태 벡터의 서로 다른 절반에서 따로 대응시킨다. 일괄 도구는 선택한 물리량 하나만 모든 링크에 적용한다. 실패한 편집은 마지막 유효 설정과 수신 결과를 보존하고 실행을 막는다.

실제 사슬 cascade 프리셋은 기존 `expandedModels-factory.ts`의 정의를 읽는다. 원래 4링크 질량·길이·초기조건·간격 0.003 s·기간 10 s를 유지하며 운동방정식을 복제하지 않는다. 새 UI의 기본 설정은 작은 각도 분포이며 이것을 legacy cascade 프리셋으로 표시하지 않는다.

## 물리 계약과 표시

- 계산: 삼중은 `rhsTriple`/`energyTriple`, 사슬은 `rhsChain`/`energyChain`. 실행별 질량행렬 workspace를 재사용한다.
- 상태: N개 아래 수직선 기준 절대각 뒤에 N개 각속도가 온다. 회전 횟수를 없애는 각도 정규화는 하지 않는다.
- 좌표: 실제 위치는 m, 위쪽 y가 양수다. 애니메이션에서만 화면 y를 반전하고 전체 길이에 맞춰 축소한다.
- 에너지: 고정점 높이가 위치에너지 영점이다. 감쇠는 토크 계수 kg·m²/s이며 감쇠 중 에너지 변화를 수치 보존 오차라고 해석하지 않는다.
- 적분: 실제 비교 검증한 RK4·RK2·명시적 Euler를 제공한다. 시간 간격은 1e-6–0.05 s, 관찰 시간은 최대300 s, 총100,000 단계 이하다. 마지막 부분 단계는 종료 시간에 맞춘다.
- 입력: 질량·길이는 0.001–1000 kg/m, 각도는 ±1e6 rad, 각속도는 ±1e4 rad/s, 감쇠는 0–1000 kg·m²/s이다. 중력은 삼중에서 0–1000 m/s², 사슬에서는 기존 엔진과 같이 0보다 커야 한다. 범위 안이어도 질량행렬의 수치 조건이나 비유한 계산으로 실행이 거부될 수 있다.

상태/시간과 위상 그래프에서 1–N 중 원하는 링크를 선택한다. 에너지 그래프는 전체 사슬을 다룬다. 작은 화면에서도 축의 의미·단위·기록 범위는 본문 텍스트로 읽을 수 있고, `모든 링크 수치 상태`와 CSV에는 모든 링크의 값이 있다. 이후 단계의 카오스·연구 분석을 미리 구현하지 않았다.

## Worker와 성능

시간 적분은 전용 product worker에서 수행한다. 한 요청은 최대64단계이며 약8 ms가 지나면 다음 요청으로 양보한다. 단일 기존 물리 단계 자체는 분할하지 않는다. 한 번에 한 요청만 전송하고 15초 무응답을 오류로 처리한다. 진행·오류 응답은 실행 ID와 순서를 검사한다.

일시정지는 현재 묶음을 마무리한 뒤 같은 worker 상태를 유지한다. 취소·reset·오류·화면 이탈은 worker를 종료하며 늦은 응답을 무시한다. 오류는 마지막 유효 수신 상태를 보존한다. 취소한 실행을 재실행하면 초기조건에서 시작한다. 화면 이탈 후 돌아오면 현재 설정과 보관함 비교 설정만 복원하며 worker와 궤적은 새로 만든다. 페이지 내 복귀 설정 캐시는 최근8개 실험이며 실험당 비교 설정은 최대12개다. 시스템·공유 링크별로 분리하고 새로고침하면 이 메모리 캐시는 사라진다.

기록은 요청 sampleEvery의 정수배 간격으로 최대2,001개 이하로 축약한다. 초기 표본과 마지막 수신/종료 상태는 포함된다. CSV는 **기록한 표본**이며 모든 적분 단계를 담는 파일이 아니다. 마지막 표본의 시간 간격은 더 짧을 수 있다. SVG는 선택된 설정과 첫 번째 링크의 시간 그래프를 담고 선을 약600점 이하로 추가 축약한다.

밀집 질량행렬은 N² 메모리와 직접 해법의 N³ 연산 비용을 가진다. 이 컴퓨터(Intel Core Ultra 7 256V, Windows, Node26.3.0)에서 128링크 RK4의 50단계 측정은 중앙값 약1.65 ms/단계, 최대약2.64 ms였다. 이 수치는 특정 실행의 Node 측정이며 브라우저 FPS·다른 기기·최악 조건의 성능 보장이 아니다. `scripts/redesign/measure-chain-performance.ts`로 다시 측정할 수 있다. 실제 브라우저 128링크 첫 표본과 취소 응답은 E2E 첨부에 별도로 기록한다.

## 저장·파일·원본 보존

S03 `pendulum-experiment/v1`을 그대로 사용하며 새 모델 버전 `chain-model-v1`, 적분기 버전 `chain-integrator-v1`을 명시한다. masses/lengths/theta/omega는 SI 벡터, g/gamma는 SI 스칼라다. seed·provenance·분석 설정·시작 시간·표본 간격을 저장·공유 왕복에서 보존한다. 새 UI가 실행하지 않는 분석 설정도 파일에서 임의로 지우지 않는다.

브라우저 저장 키는 `pendulum-product/chain/v1/{systemId}`다. 손상·미래·다른 시스템 데이터는 덮어쓰지 않고 JSON 다운로드를 안내한다. 상태 파일은200 KB 이하이며 알 수 없는 필드·버전·옵션, 잘못된 단위·배열 길이·비유한 값·prototype 오염 입력은 거부한다. CSV는 고정 헤더와 유한한 숫자로만 생성한다. 파일을 가져오기 전에 검증을 마치며 실패는 현재 설정과 원본을 보존한다.

기존 앱의 저장·공유·preset/import/export 형식과 public API를 변경하지 않았다. 기존 형식의 포괄적 migration은 S28 범위다. 새 JSON은 초기조건 재실행 파일이며 일시정지한 solver 내부 상태를 저장하는 파일이 아니다.

## 검증과 검토

진행별 결과와 원격 commit 증거는 [S10-progress.md](stage-runs/S10-progress.md), 최종 개수·환경·보고서 SHA-256은 [S10-verification.json](stage-runs/S10-verification.json)에 기록한다.

N1–128 전수 validation/한 단계/저장 왕복, N1 해석식, triple와 N3 chain 비교, 세 적분기의 기존 엔진 직접 비교, cascade preset, 링크 대응, 100,000단계 표본 예산, 실제 물리 실패 원자성, worker 취소·오류·타임아웃을 검사했다. 기존 S01 golden과 모든 기존 단위 테스트도 회귀 범위다. Playwright는 production Chromium 데스크톱과 Pixel5 에뮬레이션에서 새 경로, 기존 core/Lab/shell, keyboard, axe, 320px, CSS200% zoom, 시각 기준을 검사한다.

S09 학습 경험 구조 승인은 사용자의 S10 요청에 따라 기록했다. 과학 전문가 검토를 대신하지 않으며 과정1의 human-reviewed는0/8을 유지한다. S10 자체는 별도의 사용자 승인 checkpoint가 아니다. 실제 screen reader 음성, 실제 모바일 기기, Firefox/WebKit, 모든 운영체제 조합은 이번 검증 범위가 아니다.

기존 보안 기준선(S01 npm high2/moderate2 및 CodeQL32), 원격 push에 표시된 기본 브랜치 GitHub 집계 high7/moderate3는 미해결이다. 이번 단계에서 dependency upgrade, 보안 수정 또는 위험 수용을 하지 않았다. 알려진 credential 패턴 검사의 결과와 범위는 verification에 기록한다.
